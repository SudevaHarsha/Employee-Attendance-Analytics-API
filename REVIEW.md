# REVIEW.md

Defects found in the starter `app/main.py` (helpers and endpoints). Line numbers refer to
the original starter (`app/main.py.orig`).

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (33-37) | Grace test uses floored whole minutes `minutes > 10`, so it is not "strictly more than 10:00". It also ignores IST and the attendance date. | Shift 09:30, punch 09:40:01 → `int(601/60)=10`, `10 > 10` is False → returns **0**, but R2 says **10**. | Compute in IST against the shift start of the attendance date: `delta = lookahead`; return 0 when `delta <= 600` seconds, else `delta // 60`. |
| 2 | `compute_work_hours` (40-41) | Uses Python `round()`, which is banker's rounding, not half-up (R4/R8). | `(punch_out-punch_in)=2.005h` → `round(2.005,2)=2.0`, spec wants `2.01`. | Integer seconds / 3600 via `Decimal.quantize(..., ROUND_HALF_UP)`. |
| 3 | `compute_overtime` (44-47) | No 30-minute minimum (R3); builds a tz-aware `end` but subtracts a naive `punch_out` → raises `TypeError`; no overnight handling; truncates toward zero instead of flooring. | Call it with shift_end 18:30, punch_out 18:35 → returns 5 (should be 0); on a naive `punch_out` it throws `can't subtract offset-naive and offset-aware datetimes`. | Recompute from IST shift end on the correct day (next day for overnight); `minutes = floor(sec/60)`; return `minutes if minutes >= 30 else 0`. |
| 4 | `punch_in` (99-121) | Check-then-insert race: no unique index, so two simultaneous punch-ins both pass `find_one` and both insert → two 201s. | Fire two identical punch-ins concurrently → two 201 responses. | Unique index `{emp_code,date}`; single `insert_one`; catch `DuplicateKeyError` → 409. |
| 5 | `punch_in` (102-103) | Date from naive **local** `datetime.fromtimestamp(...).date()`, not the IST calendar date of `punch_in` (R1); no overnight-shift rule. | Punch at 2026-07-07T02:00 IST on a 22:00-06:00 shift → should be date 2026-07-06; starter uses local date. | `MongoClient(tz_aware=True)`; `attendance_date()` converts to IST and rolls overnight punch-ins back a day. |
| 6 | `punch_in` (106-113) | `status` is a free string (accepts `ABSENT`/`LEAVE`/garbage); `late_minutes` wrong (defect #1); returns `"id": str(_id)` leaking `_id`. | POST status `ABSENT` → 201 (should be 422); response contains `"id":"<ObjectId>"`. | `PresenceStatus` enum limits to PRESENT/WFH/ON_DUTY (422 otherwise); response via `record_out()` never includes `_id`. |
| 7 | `punch_in` (101,113) | No 404 for an unknown `emp_code`: `emp["shift_start"]` raises `TypeError` → **500**, not the contract's 404. | POST punch-in for `EMP0ZZZ` → 500. | `find_one` → `HTTPException(404)` when the employee is missing. |
| 8 | `punch_in`/everything (119, 149) | BSON datetimes are returned raw; FastAPI serializes them as ISO strings, but the contract requires **epoch milliseconds** (`punch_in`, `punch_out`, `history[].at`, `history[].changes.*`). | `GET /attendance` shows `"punch_in":"2026-07-14T04:02:00"` instead of an integer. | `to_ms()` conversion in `record_out()`/`_history_out()` (including nested history change times). |
| 9 | `create_employee` (77-85) | Check-then-insert race (no unique index); no field validation (emp_code/email patterns, lengths, joined_on, shift_start!=shift_end). | Two concurrent creates of the same `emp_code` → two 201s; `emp_code:"X1"` → 201 (should be 422). | Unique `emp_code` index + catch `DuplicateKeyError` → 409; `EmployeeIn` with patterns/lengths and a `shift_start != shift_end` model validator. |
| 10 | `create_employee` (82) | `created_at = datetime.now()` is naive local and returned as an ISO string, not epoch ms. | Response `created_at` is `"2026-...T...` string, not an int. | Server UTC `now_utc()`; serialize via `employee_out()` → epoch ms. |
| 11 | `list_employees` (93) | `skip = page * page_size` is off by one page. | Default request `GET /employees` → `items: []` (skips 20 of 6) with `total: 6`. | `skip = (page - 1) * page_size`. |
| 12 | `list_employees` (94) | `total` counts the whole collection, ignoring the `department` filter. | `GET /employees?department=Engineering` → `total: 6` (should be 2). | `count_documents(filter)`. |
| 13 | `list_employees` (88-96) | No `page`/`page_size` validation (page 0 / page_size 101 accepted, R10); no `emp_code` sort guarantee; items contain ISO `created_at`. | `GET /employees?page=0` → 200 (should be 422). | `Query(..., ge=1)` / `Query(..., le=100)`; `.sort("emp_code", 1)`; `employee_out()` serialization. |
| 14 | `list_attendance` (144-147) | Loads **all** matching documents into memory and sorts in Python — O(n) memory, not usable at ~100k records. | `GET /attendance` on a large collection loads every doc; no index used. | Filter/sort/paginate in the database; `count_documents(filter)`; index `{date:-1, emp_code:1}`. |
| 15 | `list_attendance` (145) | Sort key is `date` only — no `emp_code` ascending tie-break; and it has no `date_from > date_to` validation. | Two records on the same date return in arbitrary order; `date_from=2026-08-01&date_to=2026-07-01` → 200. | `.sort([("date",-1),("emp_code",1)])`; reject `date_from > date_to` with 422. |
| 16 | `list_attendance` (142-150) | `status` is a free string (no enum validation); `id` leaks `_id`; datetimes are ISO strings. | `GET /attendance?status=BOGUS` → 200 (should be 422); each item has `"id":"<oid>"`. | `Status` enum query param; `record_out()` (no `_id`, epoch ms). |
| 17 | `health` (72-74) | Always returns 200; never pings MongoDB, so it cannot report 503. | Stop Mongo, `GET /health` → still 200. | `client.admin.command("ping")`; on failure raise 503 `{"detail":"database unavailable"}`. |
| 18 | Module scope (22) | `MongoClient(...)` created without `tz_aware=True`, so BSON datetimes come back **naive**, which feeds every date/time bug above and contradicts `DATA_MODEL.md`. | `GET /attendance` returns tz-naive strings. | `MongoClient(..., tz_aware=True, serverSelectionTimeoutMS=2000)`. |
| 19 | `EmployeeIn` / `PunchInIn` (53-66) | Pydantic models have no constraints: no `emp_code` pattern, no email pattern, plain `str` status, plain `int` (floats/seconds accepted). | `punched_at: 1783312500` (seconds) accepted; `joined_on: "not-a-date"` accepted. | `EpochMillis = Annotated[int, Field(strict=True, ge=...le=...)]`; patterns/enums on all fields. |

## Examined and judged **not** a defect

- **`IST = timezone(timedelta(hours=5, minutes=30))`** — correct for UTC+05:30.
- **`{"_id": 0}` projection in `list_employees`** — the projection is right; only the total/skip/serialization around it were wrong.
- **Returning documents with derived fields as stored numbers** — fine; those are the authoritative stored values (DATA_MODEL.md), the issue was only datetime serialization.
- **`app` title/version and module layout** — fine; startup command `uvicorn app.main:app` is unaffected.
- **Default `status` of `PRESENT`** in `PunchInIn` — matches the contract.
